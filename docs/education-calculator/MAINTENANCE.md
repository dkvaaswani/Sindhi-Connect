# Maintaining, running and deploying the calculator

## Updating fees and assumptions

All data lives in **`data/education/education-costs.json`**. Edit it, then regenerate the website data file, the Excel
workbook and the source register in one step:

```bash
python3 tools/edu-calc/build.py          # needs Python 3 + openpyxl  (pip install openpyxl)
```

Commit the JSON together with the three regenerated files. Never edit `frontend/edu-calc/education-data.js` or
`docs/education-calculator/SOURCES.md` by hand — they are overwritten.

### Add or update a university fee (`records`)

Copy an existing record and change the fields. Every record needs:

| Field | Notes |
|---|---|
| `id` | Unique, e.g. `R074`. Saved backups refer to ids, so don't reuse an old id for a different course. |
| `country`, `qualification` | Must match a name in `countries` / `qualifications`. |
| `university`, `institutionType`, `studentCategory`, `level` | Category text must match exactly for records to be averaged together. |
| `feeYear`, `feeYearStart` | Text label and the calendar year the academic year starts (used for inflation). |
| `durationYears`, `tuition`, `otherMandatoryAnnual`, `oneTimeAdmission`, `otherOneTime` | Annual amounts in `currency`. Exclude refundable deposits. |
| `livingFromRecord` + living fields | `true` only if the university publishes its own cost of attendance; then living fields are used instead of the country benchmark. |
| `sourceUrl`, `sourcePublication`, `lastVerified` | Direct official page and the date you checked it. |
| `status`, `benchmarkType`, `includeInAverage` | Set `includeInAverage: false` for historical, range, estimated-band or regulatory figures. |
| `notes` | How the number was derived and what is excluded. |

**Mark a source as outdated:** set `benchmarkType` to `"Historical"`, `includeInAverage` to `false`, and say why in `status`.
**Review verification dates:** sort or search the `lastVerified` values; the register (`SOURCES.md`) lists them all.
**Averages recalculate automatically** — the web engine computes them on load and the workbook uses formulas.

### Add a country

1. Add an entry to `countries` (currency, default student category, default duration, tuition and living inflation, note).
2. Add its currency to `currencies` and `exchangeRates.rates` (units per 1 USD) and to `assumptions.returnsByCurrency`.
3. Add at least one `livingBenchmarks` row and some `records`.
4. Run the build. Course-duration defaults are generated by the seed only once; add rows to `courseDurations` by hand.

### Add a qualification

Add the name to `qualifications`, optionally a `courseDurations` row per country, then records.

### Update an exchange rate or default assumption

Edit `exchangeRates.rates` and `exchangeRates.date`, or the values under `assumptions` / `countries`, then run the build.

### Updating the Excel file directly

Parents and you can also edit the workbook: yellow cells are inputs; *Education Cost Database* rows can be added inside
the tables (named ranges include 100 spare rows). Sheets are protected without a password (Review → Unprotect Sheet).
Changes made only in Excel are **not** copied back to the website — make permanent data changes in the JSON.

## Running locally

```bash
cd frontend && python3 -m http.server 8000
# open http://localhost:8000/education-calculator.html
```

Opening `frontend/education-calculator.html` directly from disk also works (the data is a `.js` file, not fetched).

## Testing

```bash
node --test tests/edu-calc/engine.test.js     # engine tests (Node 18+), no dependencies
python3 tests/edu-calc/excel_parity.py        # Excel vs web parity (needs LibreOffice + openpyxl + Node)
```

Add a scenario to `tests/edu-calc/parity-scenarios.json` to extend the parity check.

## Deploying

Nothing special: push to the branch Netlify deploys (currently `main`). `netlify.toml` already publishes `frontend/` with
no build step, so the new page, its scripts and the downloadable workbook go live with the push. `data/`, `tools/`,
`tests/` and `docs/` are not published.

Before pushing data changes: run the build, run both tests, and open the page once to check the console is clean.

## A future admin version

Today the dataset is a reviewed JSON file in Git, which gives version history, review and rollback for free — appropriate
for a small, slowly changing dataset. If several people need to maintain fees later, a light option that fits this
static site is a Git-based CMS (e.g. Decap CMS with Netlify Identity) that edits `education-costs.json` through a form
and opens a pull request; the build step would then run in Netlify. A database-backed admin is not justified unless
fees must change without a deploy. Whatever the tool, keep the rules: official sources only, one record per
institution/category/year, refundable deposits excluded, and every change with a source URL and verification date.
